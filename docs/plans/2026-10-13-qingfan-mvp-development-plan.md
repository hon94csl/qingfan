# 青帆首版开发计划

日期：2026-10-13

状态：工程骨架已完成。M1 的固定时间线技术渲染已实现，真实 SKU 运营验收仍待完成。M2 的素材库与手动工作台已实现；运营在桌面窗口里的真人出片、印尼语审核和人工播放签字仍未完成。M3 的网关、固定响应脚本、配音和配镜已实现；真实供应商盲测、母语审核和真实 SKU 验收未完成。M4 的步骤缓存、恢复、编码回退、发布绑定、CSV 模板和本机试用目录已实现；下方首版验收集仍未测量，不能算通过。桌面「开始自动出片」已把现有的口播、配音、配镜和导出接成一次任务，并用自制镜头在固定响应下导出两条成片。相同输入会沿用已有成片；只改 BGM 会重新导出且不再调用分析和配音。应用重新打开时，中断的步骤回到待处理。这只证明调用链能写出文件，不能算验收集通过。出片页可以手填发布绑定，并预览或导入约定的 CSV；用量只显示已知微单位和待对账次数，没有换成货币，也没有按采用成片分摊。没有店铺原始导出。已具备桌面入口、共享媒体环境检查、CLI doctor 与 render、SQLite 素材库、Go 服务和独立管理后台。

依据：[架构设计](<../TK 电商素材生产与效果回流系统 · 架构设计.md>)及本次产品讨论

## 目标与交付边界

让印尼 TikTok Shop 运营用已有商品素材，生成少量候选，修改文案和镜头后导出可发布视频。参照 NarratoAI 的分阶段生产流程，优先验证素材理解、音画匹配和人工修改成本。

首版支持一个内部工作空间、单电脑项目、`market=ID`、`locale=id-ID`。每次生成 1–3 条候选；发布和数据回流由人工配合，不等待 TikTok OAuth 或报表接口。

本计划不包含自由多轨编辑器、文生视频、参考镜头文字擦除、跨设备自动同步、自动投放、选品评分和商业计费。保留相应数据归属与版本边界，不提前实现这些模块。

## 已确定的技术决策

| 决策 | 实现约束与原因 |
| --- | --- |
| Go 单模块，Wails v2 + React/TypeScript | 媒体逻辑放在 `internal/`，命令行和桌面共用；Wails 界面在 M2 接入 |
| FFmpeg/ffprobe | M1 用 libx264 建立样片基线；分段处理后合成，硬编在 M4 按真实设备补充 |
| SQLite 保存本地业务数据 | 素材定位、草稿、任务和成片是业务记录，不能作为可随意删除的缓存 |
| 明确区分草稿与渲染时间线 | AI 输出先校验，配音后由程序装配；导出版本和资源清单不可变 |
| 一个 Go AI 服务 | 单实例 SQLite 用量库、HTTPS、可撤销的工作空间令牌；供应商密钥在服务端，客户端凭据存入系统凭据库 |
| 先验证人工可控，再接自动生成 | 固定样片 → 手动工作台 → AI 辅助，避免同时排查模型与渲染问题 |
| 分步缓存与失败恢复 | 按输入哈希和版本确定复用；原文件和成功导出不可被失败任务覆盖 |

初次应用实现时固定工具链和依赖版本，提交锁文件。当前运行命令见根 README；下列包含已有骨架及后续按需创建的包，不表示业务功能已完成。

## 依赖与推进顺序

```mermaid
flowchart LR
    M0[M0 素材与人工基线] --> M1[M1 固定时间线出片]
    M1 --> M2[M2 素材库与手动工作台]
    M2 --> M3[M3 AI 辅助混剪]
    M3 --> M4[M4 恢复与试用交付]
    M4 --> NEXT[依据试用结果规划后续]
```

M0 缺少真实素材时，M1 可先用自制片段验证技术；真实运营验收仍保持待完成，不用模拟样本替代。M3 缺少供应商凭据时，可以完成调用边界与失败场景测试，但不能宣称真实 AI 链路已验收。

### M0：素材样本与人工基线

**交付：** 一个真实 SKU、可用商品事实、自有视频、一个可选参考视频、现有流程的一条成片，以及运行机器信息。记录原素材量、拍摄/整理时间、审稿返工时间和渲染等待时间。

**文件：** `docs/validation/baseline.md`、`tests/fixtures/README.md`。真实素材放在被忽略的本地 `data/` 或项目外目录；仓库只记录匿名 ID、哈希、来源及使用说明。

**验收：** 同一批素材能够用于新旧流程对比；明确谁确认商品事实、谁审核印尼语。已有素材不足也要记录具体缺口，不要求运营先按固定数量补拍。

### M1：固定时间线到完整样片

**依赖：** M0 的样本规范。目标是先证明本地渲染协议可执行。

**实现：** 初始化 Go 模块与 `cmd/qingfan-render/`；冻结时间线 v1 和资源清单。支持一段口播配多个镜头、镜头内裁切、按段字幕、配音、BGM、竖屏合成和基础质检。先只使用预录音频，不接模型。

**文件：** `internal/timeline/types.go`、`internal/timeline/validate.go`、`internal/media/probe.go`、`internal/media/render.go`、`internal/media/subtitle.go`、`internal/media/quality.go`、`tests/fixtures/timelines/`。

**测试：** `internal/timeline/validate_test.go`、`internal/media/render_test.go`、`tests/integration/render_test.go`。

- 时间区间非法、超出镜头边界、跨 SKU、reference 来源、资源缺失或哈希变化时拒绝渲染。
- 一段两个镜头的时长正确累加，配音与字幕不超出段尾；30fps 输出边界舍入偏差不超过一帧。
- 路径含空格、中文及字幕含引号或特殊字符时正确处理，不能被解释成命令或额外滤镜。
- 输入含横竖画幅、旋转元数据、无音轨、可变帧率时得到可预览结果，必要时明确报不支持。
- 成片可由 ffprobe 读取，尺寸、帧率、音轨和时长符合清单；强制失败不覆盖已有成功文件。

**验收：** 一条固定样片从命令行完整导出，人工确认产品主体、字幕、配音和 BGM；相同资源与配置再次渲染得到内容一致的结果，不以跨编码器文件哈希相同为标准。结果记录在 `docs/validation/render-baseline.md`。

### M2：素材库与手动工作台

**依赖：** M1 的协议和媒体核心。

**实现：** 接入 Wails v2 + React/TypeScript，建立 SQLite 迁移、项目/SKU、素材与本地位置、镜头区间、草稿和成片记录。导入时探测、计算内容哈希、抽缩略图，生成候选切镜并允许人工修正。分段卡片支持选镜头、调区间、填口播、上传预录配音、预览和导出。

**文件：** `main.go`、`app.go`、`wails.json`、`frontend/src/`、`internal/store/migrations/`、`internal/store/assets.go`、`internal/store/outputs.go`、`internal/media/ingest.go`、`internal/jobs/runner.go`。

**测试：** `internal/store/assets_test.go`、`internal/store/outputs_test.go`、`internal/media/ingest_test.go`、`frontend/src/components/SegmentCard.test.tsx`。

- 重复导入同一内容可复用探测结果，来源与使用权不能因去重被错误提升。
- 文件移动可重新定位；同路径替换内容使旧分析失效；错误 SKU 和 reference 镜头不可选入成片。
- 关闭再打开应用后草稿与输出记录仍在；修改草稿不覆盖已经导出的成片版本。
- 卡片修改准确传给媒体核心；错误有可理解的提示，键盘可完成主要操作。

**验收：** 运营能在桌面端用固定素材和录音手工完成一条成片；替换某段镜头后预览和导出反映新内容。此时不依赖 AI 服务。

### M3：素材理解、脚本、印尼语配音与自动配镜

**依赖：** M2。先用真实印尼语脚本做小规模 TTS 盲测，选择首个供应商和音色。

**实现：** Go AI 网关提供鉴权、并发/额度控制、调用记录，接一个视觉/文本供应商和一个 TTS 供应商。令牌只存哈希并可撤销，用量存入服务端独立 SQLite；部署时配置 HTTPS，客户端使用系统凭据库。按镜头抽帧分析用途、动作和卖点，允许人工修正；可选参考视频拆结构。基于商品事实和可用镜头生成 1–3 条候选口播及回译；运营审核后生成分段 TTS，按实际时长装配镜头，生成字幕与配方。

**文件：** `cmd/qingfan-server/`、`internal/ai/gateway.go`、`internal/ai/analysis.go`、`internal/ai/script.go`、`internal/ai/tts.go`、`internal/ai/usage.go`、`internal/ai/prompts/`、`internal/timeline/assemble.go`、`frontend/src/components/ScriptReview.tsx`。

**测试：** `internal/ai/gateway_test.go`、`internal/ai/script_test.go`、`internal/ai/usage_test.go`、`internal/timeline/assemble_test.go`、`tests/integration/generation_test.go`。

- 非法模型 JSON、虚构素材 ID、越界时间、未知商品事实引用被拒绝或进入人工处理；不能默默替换为第一个素材。
- 未授权请求、撤销后的令牌、跨租户访问和并发超额在服务端被拒绝；密钥不出现在前端包或日志中。
- 配音长于一个镜头时可组合多个有效镜头；总画面仍不足则提示缺口，不延长出界、循环或跳段。
- 中文回译随文案失效重算；音色变化使对应配音失效；相同输入命中缓存时不重复调用计费。
- 超时、限流、无效音频和用量未知均有明确状态；记录失败与重试费用，限制重试次数。

**验收：** 一个真实 SKU 从素材分析到 3 条候选、人工修改、印尼语配音、配镜、导出全部走通。母语审核记录自然度、商品名和数字发音问题，运营记录采用与拒绝原因；不会因为生成了文件就默认可用。记录在 `docs/validation/generation-pilot.md`。

### M4：局部重做、恢复、人工回流与试用包

**依赖：** M3。将已经能出片的流程交给运营连续使用。

**实现：** 完善步骤产物缓存、取消和恢复，按真实目标机器检测硬件编码并提供软件回退。补充成片清单、人工发布链接绑定和一份约定的 CSV 效果导入模板。制作目标平台试用包，携带固定媒体工具与字体，记录安装和日志获取方式。

**文件：** `internal/jobs/cache.go`、`internal/jobs/recovery.go`、`internal/media/encoder.go`、`internal/reporting/publications.go`、`internal/reporting/csv.go`、`tests/fixtures/reporting/`、`build/`、`docs/validation/pilot-report.md`。

**测试：** `internal/jobs/recovery_test.go`、`internal/media/encoder_test.go`、`internal/reporting/csv_test.go`、`tests/integration/recovery_test.go`。

- 改一段口播只重算受影响的内容；改 BGM 不重新分析素材或生成 TTS。
- 中断进程、取消、磁盘写入失败后不残留“成功”的坏产物；重启只恢复未完成步骤。
- 必要片段、配音或字幕失败不能静默跳过；缓存清理不删除原文件、已导出成片或仍被引用的资源。
- 模拟硬件编码不可用能回退；真实目标机器上测试导出、内存占用和响应情况。
- 发布绑定指向不可变的成片版本；CSV 重复导入不重复累计，错误行、缺字段、未绑定视频有预览提示，缺失值不当零。
- 在无开发工具的目标机器验证安装、启动、预览、导出及日志获取；未验证的平台不标为支持。

**验收：** 完成下方首版验收集，提交试用记录和已知限制。API 接入失败或未申请不影响本阶段完成。

## 首版验收集

以下为首轮试用目标，尚未获得实测结果；如需调整，以真实样本记录原因，不用降低测试范围掩盖失败。

| 项目 | 通过条件 |
| --- | --- |
| 技术闭环 | 固定样片和 AI 生成样片均能在目标机器渲染、播放并追溯输入资源 |
| 内容完整 | 零静默缺段、零错 SKU；口播对应画面，必要字幕与音轨存在 |
| 小批量试用 | 至少 3 个真实 SKU，每个生成 3 条候选，记录全部采用/拒绝原因 |
| 采用情况 | 初始目标为 9 条中至少 6 条经运营及印尼语审核后可发布；未达标则继续修正生产链 |
| 人工成本 | 对同批素材比较到可发布成片的总人工时间，中位数不高于现有流程；渲染等待另列 |
| 恢复与修改 | 中断后可恢复；局部修改复用未变化产物，已成功输出不会损坏 |
| 成本可见 | 能查看项目总费用与采用成片分摊，含未采用候选和失败重试 |
| 人工闭环 | 至少一次成片发布链接绑定和 CSV 导入，不要求取得 TikTok API 权限 |

自动检查覆盖结构、时长、文件完整性和失败处理；人工检查覆盖音画语义、产品主体裁切、印尼语自然度和发布意愿。两者都通过才算完成。

## 实施检查与提交方式

每个里程碑单独提交可验证的交付，测试路径随功能创建，不预建空测试。Go 媒体核心单元测试与真实 FFmpeg 集成检查分开；前端接入后运行类型检查、组件测试和构建，桌面阶段补充实际窗口操作验收。

外部模型测试使用固定响应覆盖失败场景；真实调用作为单独的有限额验证，不能把模拟结果计为模型质量验收。文档中的候选数量、采用率和耗时必须由试用记录支持。

依赖升级、自动更新和新增供应商不混入当前功能提交。代码实现开始后再配置对应 CI；本次仅初始化仓库与文档，不声称任何应用测试已通过。
