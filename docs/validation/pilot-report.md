# 试用记录

日期：2026-10-13

里程碑：M4 的步骤缓存、恢复、编码回退、发布绑定、约定 CSV 和本机试用目录。首版验收集没有实测，这次不能算通过。

## 这次证明了什么

在这台开发机上，`make test` 通过。Go 测试覆盖任务恢复、编码参数、CSV 规则、数据库里的发布绑定，以及关闭后再打开数据库。前端组件测试和两个生产构建也通过。浏览器里检查了新增表单。没有启动 Wails，也没有人眼播放成片。

- 改一段口播只重做该段配音、装配和合成。改一个镜头的裁切只重做该段装配和合成，不重做文案和配音。改 BGM 或字幕样式只重做最终合成。素材分析的键单独变化时，不重做配音。
- 写入失败会删掉临时文件，已经存在的成片内容保持不变。进度百分比不能把步骤标成成功。没有落盘产物的“成功”步骤在恢复时回到待处理。失败、取消和待审核保持原状态。
- 缓存清理不删除原素材、已导出成片和仍被保留的步骤文件。指向原素材的符号链接被移除后，原素材还在。
- 模拟硬件编码器不可用时，参数回到 libx264，并且不带 VideoToolbox 的选项。未设置 `QINGFAN_ENCODER` 时，渲染测试仍要求 libx264。
- 本机 `/Users/hon/.local/bin/ffmpeg` 版本是 `ffmpeg version 9.0.2-https://www.martin-riedl.de`。用它把一帧 64×64 画面编码为 `h264_videotoolbox` 时，进程退出码为 0。这不是 1080×1920 成片，也没有测量内存占用或界面响应。产品导出没有改用这个编码器。
- 发布绑定必须指向已经存在的成片。短链接可以留空，手填完整视频编号即可。同一成片可以有两条发布记录，成片文件和清单不变。
- CSV 只认 `tests/fixtures/reporting/metrics.csv` 这一份表头。空的播放量或成交额在库里是 NULL，写成 `0` 的才是零。缺少视频编号、坏日期和坏数字不会导入。同一键不会累计第二次。同一份文件再导入时接受行数是 0。两个来源的金额分开保存，没有相加。预览不写库。
- 配音缓存的文件名是哈希，不含口播原文。命中已有文件时不再调用供应商。失败的写入不会换掉已经成功的缓存。步骤失败记录的是「配音失败」，不是整段口播。
- 浏览器打开 `http://127.0.0.1:5173/`。视频编号可以输入。点击「预览回流」「绑定发布」「导入回流」都会提示需要在桌面应用里打开。页面上有「发布与回流」。

`make trial` 生成了 `build/trial/`。该目录被 Git 忽略。里面是上述 ffmpeg 与 ffprobe 9.0.2 的副本、`Lato-Regular.ttf` 和 `OFL.txt`，以及 `docs/trial/README.md`。没有在一台不带开发工具的机器上安装。

## 命令

```sh
make test
make trial
go test ./internal/media/ -run TestInstalledFFmpegProbeFallsBackOrUsesVideoToolbox -count=1
```

`make test` 包含 `go test ./...`、后台请求测试、桌面组件测试，以及两个前端的类型检查和生产构建。集成测试里的恢复用例不依赖再渲染一条成片；既有渲染测试仍使用 libx264。

浏览器预览用的是 Vite `127.0.0.1:5173`，检查后已停止。没有调用 macOS 钥匙串。

## 限制

- 首版验收集一项都还没有实测：没有 3 个真实 SKU，没有 9 条候选里的采用记录，没有人工时间中位数，没有人眼播放，没有印尼语母语审核，也没有项目费用。未知费用保持未知，不能写成 0。采用条数为 0 时也不做分摊。
- 没有供应商凭据，没有做过真实印尼语 TTS 盲测。
- 一份 CSV 只要已经导入过至少一行，再次导入整份文件时不会补进上次被拒绝的行。应先绑定视频再导入，或改过文件后再导入。
- 只接受这一份表头。没有拿店铺或广告后台的原始导出做过对照。不同来源不加总。这个模板也不把成交额解释成广告增量。
- VideoToolbox 只验证了一帧探测可以启动。默认成片仍是 libx264。不同硬件编码器不保证文件字节相同。
- 试用包没有签名，也没有公证。没有 Windows 包，没有自动更新，没有远程崩溃上报。复制进来的 FFmpeg 构建带有 GPL 配置；把目录交给别人之前要单独确认分发许可。
- 管理后台仍然只检查服务是否在运行。
- 没有开始更多语言、自动回流、推荐、投放或对外多租户。
